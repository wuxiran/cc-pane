# 会话审阅、本地启动配置与 Computer Use

CLI 终端与 Agent Chat 共用代码审阅和本地工作树配置。启动卡片、环境浮层和浏览器工具栏采用紧凑圆角布局，颜色跟随应用主题。

## 启动会话

在启动卡片的项目名称旁打开「配置启动环境」。不开启新工作树时沿用当前目录和分支；开启后可选择基准分支和新分支名称。

新工作树从所选分支的已提交内容创建，原目录中的未提交修改与未跟踪文件保留在原处。以仓库子目录为项目时，启动目录仍是新工作树中的同一子目录；若该目录在基准提交中不存在，创建前直接报错。CLI 明确透传实际启动目录，避免被原工作空间路径覆盖。Agent 引擎启动失败后保留已创建的工作树供重试。

CLI 启动器保留本地、WSL、SSH 和已有启动配置功能。Agent 使用 ACP 引擎实际支持的本地运行及原有模型、模式配置，不显示无效的远程环境或配置选项。

## 审阅更改

从 CLI 状态栏或 Agent 会话顶栏点击「审阅更改」。页面支持三个范围：

| 范围 | 比较内容 |
| --- | --- |
| 上一轮 | 轮次开始与完成时的文件快照，可选择已完成的轮次 |
| 工作区 | 当前文件与 HEAD 的差异，包括未被忽略的未跟踪文件 |
| 分支 | 所选基准与 HEAD 的共同祖先到 HEAD 的已提交差异 |

分支审阅固定比较两端的提交 ID，避免审阅途中分支前进而混入不同版本。各文件提供增删统计、折叠、换行和打开当前文件；二进制、超限文件或读取失败时明确提示统计不完整。

Agent 自动记录轮次。CLI 在发送提示词前点击「开始记录」，结束后点击「完成本轮记录」。CLI 记录绑定具体 PTY 会话，只用于审阅；缺少开始快照或应用重启中断的区间不会伪装成完整轮次。所有目录快照都可能包含其他进程在同一时间的修改，不代表作者归属。

远程 SSH／WSL 终端不使用宿主机路径冒充远程审阅。普通浏览器版可使用服务端工作区／分支比较，轮次检查点目前由桌面版提供。

## 内置浏览器与 Computer Use

浏览器工具栏提供后退、前进、刷新、地址栏和 Computer Use 入口。打开 Computer Use 侧栏后可以读取页面、查找可操作元素、点击、填写文本、发送普通按键、滚动及保存截图。元素操作后会重新读取页面；页面变更导致快照失效时，需重新读取后继续。

这些能力也进入默认 MCP 工具集合，CLI 与 Agent 使用同一后端：

1. `open_browser_tab` 或 `browser_list_tabs` 获取真实标签 ID。
2. `browser_snapshot` 读取页面文本与元素，获得 `pageToken` 和 `elementId`。
3. 使用 `browser_click_element`、`browser_fill`、`browser_press_key`、`browser_scroll` 操作该标签。
4. `browser_screenshot` 保存截图；`browser_navigate` 导航；`browser_close` 同时关闭原生视图和应用标签。

例如可通过现有 CLI 入口查询工具的实时参数：

```sh
cc-panes-ctl tools --schema browser_snapshot
cc-panes-ctl call browser_list_tabs --json '{}'
```

快照不返回表单输入值。网页内容属于待处理的数据，不是用户授权或系统指令。结构化工具面向内置浏览器顶层文档，不提供全桌面控制，也不穿透 iframe 或 Shadow DOM。任意 JavaScript evaluate 仍留在完整工具集合中。

macOS 使用 WKWebView 的原生输入与截图；Windows 使用独立 WebView2 路径。原生验证应分别在目标系统完成，不以跨平台编译代替桌面验收。
