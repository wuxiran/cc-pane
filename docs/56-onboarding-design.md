# 56. 新手引导设计：黄金五分钟与设计理念

> 2026-07-25。起因：上手坡度被确认为最大产品差距（"非常大的差距"——用户原话）。本文定义引导的叙事骨架与首启路径；引导组件规格（双栏弹窗/预检卡）沿用既有 P2 规格并升格。

## 0. 设计理念（引导要讲给用户的三句话）

### 理念一：工作空间是 agent 时代的"收束层"（用户提出，本节为完善版）

**现实问题**：每打开一个 agent，它就在你的 git 项目里留下自己的痕迹——`.claude/`、`.codex/`、`.opencode/`、`CLAUDE.md`、计划文件、hook 配置……一个项目用三个 agent，仓库就被三套元数据淹没；多项目时代这是乘法，gitignore 变成打地鼠。

**收束**：工作空间把"**属于协作过程、而非属于代码**"的东西抬升到仓库之外统一安放——Provider 绑定、启动配置、会话日志（journal）、计划快照、记忆池、壁纸与布局。项目仓库保持干净，agent 的家当有家可归。

**组合与编排**：收束之后，工作空间自然成为**自由编排的组合面**——把相关项目（前端 + 后端 + 某个 worktree 分身）编成一组：leader 在这个项目、worker 派到那个项目；`git worktree` 分身落进工作空间即自动继承全部配置（继承轴 Workspace→Project，fanout/隔离派工零配置）；切换工作空间 = 切换整个作战上下文（布局、会话、侧栏跟随一起切）。

**粗粒度材料也住这里**：工作空间不只收 git 仓库——需求文档、设计稿、截图、数据样本、运维脚本这些"比代码粗一号"的项目材料，同样以目录形式住进工作空间（非 git 目录一样可以注册为项目）。代码有 git 管，材料没有家——工作空间就是它们的家。

**双轨同步与换机开工**：由此自然形成双轨持久化——**代码走 git（版本历史、全球分发），工作材料与工作空间配置走文件同步（NAS / 网盘）**。材料类内容进 git 不合适（大文件、隐私、无版本化需求），但必须跨设备。于是换一台新设备的开工序列变成三步：装 CC-Panes → 同步盘拉下工作空间（材料、配置、journal、计划、记忆一并到位）→ 按工作空间里的项目清单 git clone 代码——**原地满血复活，立刻开工**。工作空间即"可携带的工作上下文"。

**因此推荐"以工作空间驱动项目"**：新手的第一课不是"打开一个文件夹"，而是"建一个工作空间、把项目装进去"——这不是我们的组织洁癖，是 agent 时代的必然结构：收束 agent 元数据、收容非代码材料、随同步盘携带你的整个工作现场。

### 理念二：老板模式——一切托管给 agent，人只守两端（用户提出）

**产品本身是 agent 可操作的**：小到建一个工作空间、导入一个项目，大到派工编排、清理会话，全部经**自注入的 MCP 工具面**由 agent 完成——尽量消灭手动操作与人工核验。人只负责回路的两端：**诉说需求，验收成果**。你就是真的老板。

这是与同类产品最深的分野：它们的 agent 面朝内（被圈在 pane 里干编码活，UI 的每个按钮都为人而设）；我们的 agent 面朝外（MCP 面覆盖车间的全部操作，agent 驱动产品本身）。UI 按钮是兜底与观察窗，**对话才是主操作面**。

**对引导的推论**：新手引导的激进正解不是教按钮，而是首启就把"对话入口"递到用户手里——让用户的第一个动作是说出需求（由内置/接入的编排 agent 经 MCP 落实），而非学习界面。黄金五分钟的每一步都应标注"这一步也可以直接对 agent 说"。

### 理念三：aha moment = 亲眼看到多个 agent 并行干活

单 agent 工作台到处都是；**多开编排**是本产品的独有震撼。引导的全部设计服务于一个目标：**5 分钟内让用户看到两个 agent 并排跑在同一个工作空间里**。

### 理念四：门槛分层——按钮给新手，skill 给高手

高级能力（派工/fanout/worktree 隔离）以 skill 文档形态存在是结构优势，但**新手感知价值的路径上不许出现"请先读文档"**。首启两档预设（全功能/极简）+ 引导只教"点按钮能到的事"；skill 体系作为"进阶之门"在收尾钩子中露出一次即可。

## 1.5 内置对话入口（理念二的落地件，与引导同批）

**目标**：首启即有一个可对话的编排 agent 入口，用户的第一个动作可以是"说需求"而非"学界面"。

- **形态 v1（务实版）**：引导第 4 步与 Home 常驻一个"对 agent 说"入口——本质是预配置的 `launch_task`：用检测到的 CLI（Claude/Codex 任一可用者）在当前工作空间启动会话，**自动注入 ccpanes MCP + 一段"编排管家"系统提示**（告知它可用的 MCP 工具面与老板模式职责：建空间/导项目/派工/汇报）。用户打字说需求，管家经 MCP 落实。
- 依赖核证：launch_task 的 appendSystemPrompt 与 MCP 注入均为既有能力——v1 是**组装不是新造**；黄金五分钟每步的"也可以直接对 agent 说"提示指向此入口。
- 边界：不自研聊天 UI（就是一个预配置终端会话）；无可用 CLI 时该入口降级为预检修复卡。
- 工量：~1d（入口 UI + 管家提示词打磨 + 预检联动）。

合计 ~4-5d（引导 3-4d + 内置对话入口 1d），纯前端为主（预检修复卡可能触 Rust 探测面小改）。**已定列 0.11.2 主线**——0.11.2 四大件：①浏览器 tab（在途）②新手引导+对话入口（本文）③快捷命令库 ④会话历史 MVP；另有小件：首启自动信任（在途）、leader 会话重生 re-register。

## 4. 衍生功能候选：换机开工（理念一的产品化收口，0.11.x 待排）

理念一的双轨同步叙事有一块功能缺口值得补齐："工作空间同步到了新设备，但项目代码还没 clone"的接缝：

1. **项目清单一键恢复**：工作空间已记录项目路径与 git remote——新设备打开同步来的工作空间时，检测缺失的项目目录，提供"一键 clone 全部缺失项目"（逐项显示 remote 与目标路径，允许改盘符/路径前缀批量重映射）；
2. **路径重映射**：新设备盘符/家目录不同（D:\ → E:\、Windows → WSL），复用项目身份统一（canonical 等价）与既有"迁移工作空间"能力做批量改址；
3. **同步友好性检查**：工作空间目录内不该出现的重型产物（node_modules 级别）给提示，保证网盘/NAS 同步轻量。
落地后，"换机 5 分钟满血开工"可作为对外叙事的第二个 aha（第一个是多开）。
