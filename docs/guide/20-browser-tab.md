# 20. 应用内浏览器标签：让 AI 自己看网页

> 分屏里除了终端和编辑器，还能开一个**真正的浏览器**——地址栏、前进后退、开发者工具都在。它的价值不在于「少开一个 Chrome」，而在于：**AI 能通过 MCP 打开它、导航它、点它、截它的图、在它里面跑 JavaScript**。你的 dev server 起来了，让 Claude 自己去看页面长什么样。

## 先消歧：这不是 [16 篇](16-web-and-mobile.md) 说的那个「浏览器」

手册里有两处提到浏览器，是完全不同的两件事，别搞混：

| | [16. Web 端与手机端](16-web-and-mobile.md) | 本篇 |
|---|---|---|
| 说的是 | **外部**浏览器（Chrome / Safari）打开 CC-Panes 的 Web 端 | CC-Panes **应用内**的一个标签页，里面嵌了个浏览器 |
| 你在里面看到的 | CC-Panes 自己的界面 | **任意网页**：你的 dev server、文档站、后台 |
| 谁在操作 | 你 | 主要是 **AI**（经 MCP），你也能手动导航 |

一句话：16 篇是「用浏览器打开 CC-Panes」，本篇是「在 CC-Panes 里打开浏览器」。

---

## 什么时候用得上

- **让 AI 看见自己写的界面**：跑起 dev server，让 Claude 打开 `http://localhost:5173`，截图，然后根据截图继续改样式
- **让 AI 验证改动真的生效**：改完接口，让它打开页面、点几下、跑一段 JS 读取页面状态，而不是只说"应该好了"
- **边看文档边写代码**：分屏左边终端右边文档站，不用在窗口之间来回切
- **调试**：内嵌的开发者工具就是完整的 DevTools

## 怎么开

**当前版本没有「新建浏览器标签」这个按钮。** 浏览器标签只能由 **AI 通过 MCP 工具**打开——这是有意的设计取向（它首先是给 AI 用的工具），但也意味着你得先有一个连着 CC-Panes MCP 的 CLI 会话（[怎么接上见 MCP 编排篇](mcp-orchestration.md)）。

对 Claude 说一句就行：

> 帮我在 CC-Panes 里打开 http://localhost:5173

它会调用 `open_browser_tab`，**在你当前活跃的窗格里**新开一个标签，图标是个地球，标题默认取网站域名。标签开在主窗口的当前布局里；如果当前不在分屏视图，会自动切回去。

一些限制，都是硬性的：

- **只接受 `http` / `https`**。`file://`、`app://` 之类会直接报错。
- 地址栏里你输 `localhost:5173` 这种不带协议的，会**自动补 `http://`**（本机 / 内网地址补 http，其它域名补 https）。
- **仅桌面应用可用**。在 Web 端（浏览器里的 CC-Panes）打开这类标签，只会显示一句「浏览器标签仅在桌面应用中可用」。

## 你能在里面做什么

标签顶部是一条工具栏：

1. **后退 / 前进 / 刷新**
2. **地址栏**——可以直接编辑，回车导航。左边有个安全标识：锁形（安全的 HTTPS 页面）、显示器形（本机或内网页面）、三角警告（不安全的 HTTP 页面）
3. 最右 **`</>` 按钮**——打开开发者工具（提示上标着 F12）

页面标题变了，标签页的名字会跟着变；你在页面里点链接跳走了，地址栏也会跟着更新。

**关掉标签 = 关掉这个浏览器**，里面的登录态、填了一半的表单都没了。但**重启应用后标签会回来**，并停在你最后停留的那个网址上。

## AI 能做什么（MCP 工具）

这才是重点。CC-Panes 给 AI 暴露了 5 个浏览器工具，都要带上 `open_browser_tab` 返回的 `tabId`：

| 工具 | 干什么 |
|---|---|
| `open_browser_tab` | 开一个新浏览器标签，返回 `tabId` / `url` / `title` |
| `browser_navigate` | 让已有标签跳到另一个网址 |
| `browser_click` | 在页面可视区域按坐标（逻辑 CSS 像素）左键单击 |
| `browser_evaluate` | 在页面上下文里执行任意 JavaScript，返回结果 |
| `browser_screenshot` | 截当前可视区域，存成 PNG，返回文件路径 |

截图落在截图目录里（`~/.cc-panes/screenshots/`，dev 版是 `~/.cc-panes-dev/screenshots/`），AI 拿到路径后可以自己读回来看。

典型对话：

> 起一下 dev server，然后在 CC-Panes 里打开首页，截个图给我看看现在长什么样。

> 那个提交按钮点了没反应，你打开页面自己点一下，把 console 里的报错读出来。

### 两个必须知道的前提

**一、`browser_evaluate` / `browser_screenshot` / `browser_click` 目前只在 Windows 上可用。** 这三个走的是 WebView2 的 DevTools 协议，macOS / Linux 上会直接返回「native WebView2 CDP is only available on Windows」。`open_browser_tab` 和 `browser_navigate` 三平台都能用。

**二、`browser_evaluate` 是在页面上下文里跑任意 JS。** 它能读也能改页面上的任何数据，包括登录态里的东西。只对**你信得过的页面**和**你看得懂的脚本**用它——本地 dev server 是最合适的场景。（返回结果最大 64 KiB，超了会被截断。）

## 常见问题

- **我想自己开一个浏览器标签，找不到按钮？** 当前版本确实没有。让 AI 帮你开一个，之后地址栏就归你用了。
- **打开报错说不支持这个协议？** 只支持 `http` 和 `https`。想看本地文件，用 [文件编辑器](06-files-and-editor.md)，或者起个静态服务器。
- **AI 说截图 / 执行 JS 失败？** 先看是不是在 macOS / Linux 上——这三个工具只支持 Windows（见上）。Windows 上仍失败的话，多半是 `tabId` 不对（标签已经被关掉了），让它重新 `open_browser_tab` 拿一个新的。
- **右键菜单弹出来的时候，浏览器画面消失了一下？** 内嵌浏览器是一层原生视图，压在界面上层；弹出菜单时会暂时把它藏起来，免得菜单被盖住。菜单关掉就恢复，不是崩了。
- **页面在标签里能打开，但 AI 说它看不到内容？** `browser_screenshot` 截的是**当前可视区域**，不会滚动全页。让它先 `browser_evaluate` 滚到目标位置再截。
