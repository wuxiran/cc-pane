# 14. Resume：恢复历史会话

> 昨天那个跑到一半的 Claude / Codex，今天能**接着跑**，不用从头再来。

## 解决什么

- 续上之前的对话历史和分析，不重复“读一遍代码、理一遍思路”
- 省 context、省时间

## 在哪找

点左侧 ActivityBar 的 **最近启动**（历史图标）视图，里面列着你的启动记录，每条都可以**恢复（Resume）**。也可以直接对 Claude 说“恢复之前那个会话”，它会帮你从历史里找。

## Resume 和"新建"有什么区别

| | Resume 恢复 | 新建 |
| --- | --- | --- |
| 上下文 | 带着上次的对话历史和环境 | 干净、空白 |
| 适合 | 接着上次干 | 全新任务 |

## 什么时候能恢复

- 会话**还活着**（没退出）→ 能恢复，接着聊
- 会话**已经退出**了 → 恢复不了，只能新建一个

## 注意

- 恢复时要用**对应的 CLI 和运行环境**：上次是 Codex + WSL，就照原样恢复，别换成 Claude + 本机，否则接不上。CC-Panes 从历史记录里会带着这些信息，一般不用你操心。
- 想确认某个会话还在不在，可以在“最近启动”里看它的状态。

## 创建聊天分叉

想保留已有上下文，另开一条独立的讨论线，可以创建聊天分叉：

- **CLI 终端**：右键 Claude Code 或 Codex 的终端标签 →「创建聊天分叉」。分屏标签使用当前选中的终端会话；需要先取得该会话的对话 ID。
- **Agent Chat**：会话顶部「更多」→「创建聊天分叉」。等当前回复结束后操作；引擎需要支持分叉。

两种入口都可以选择「在当前项目目录分叉」或「创建独立 Git 工作树后分叉」。前者共享项目文件，后者使用独立分支和目录，并复制当前未提交修改及未被忽略的新普通文件。工作树模式需要已有提交的本机 Git 仓库；不复制依赖等忽略文件。遇到未跟踪符号链接或嵌套仓库时会报错，不会留下不完整的工作树。

分叉拥有独立的会话 ID，后续消息不会追加到父会话。当前 CLI 支持 Claude Code、Codex；WSL 支持同目录分叉，SSH 分叉和 WSL 工作树创建暂未接入。Agent Chat 的 Claude 和 Codex 使用固定版本的原生分叉接口，其他引擎按其声明的能力开放入口。
