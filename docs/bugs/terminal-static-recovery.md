# 终端恢复期间静态展示

终端的一小段最终内容可能对应数百万字符的进度刷新、擦除和光标移动指令。
原先 resync 在可见 xterm 上 reset 并逐块重放，用户会看到历史从头滚到底部。

## 恢复行为

- 重同步、已有会话挂接、休眠唤醒和冷恢复期间，保留当前视口的静态画面。
- xterm 继续解析恢复数据，等待写入回调完成后，一次性展示最终画面。
- 阅读历史时优先定位原先的首行内容；该行已淘汰时，将原行号限制在可恢复范围内。
  原先位于底部的视图继续跟随最新输出。
- 恢复中收到的适应大小请求合并并延后，避免 resize 打断历史控制指令的解析。
- 成功恢复、重新锚定输出序号后，主视图立即尝试保存解析后的静态 checkpoint。
  后续恢复可以读取精简快照与增量。原有世代、输出完成和上传去抖检查继续生效；上传前重新检查当前写入权限，
  防止主视图转为只读后仍覆盖共享快照。

DOM 直接复制已画好的节点。WebGL 在 onRender 回调内复制画布，避免复制到已被清除的
绘图缓冲；无绘制回调时在 100ms 后退回静态文本。画面交换等待两帧，另有 100ms 上限，
窗口隐藏、失败及卸载均不会无限等待动画帧。恢复期间保留原终端实例及输入焦点。

这是现有 checkpoint 恢复机制的补全。没有新增独立的聊天记录数据库；历史保留范围和
旧后端不支持 checkpoint 时的限制保持现有契约。

## 验证

单元测试位于 `terminalReplayPresentation.test.ts` 与 `terminalRecoveryCheckpoint.test.ts`，
并回归恢复、布局调度、休眠和 TerminalView 的测试。

真实浏览器回归：

```sh
node scripts/smoke-terminal-static-replay.mjs [Playwright模块入口绝对路径] [浏览器channel]
```

默认从当前 Node 环境读取 Playwright；也支持 `CCPANES_PLAYWRIGHT_MODULE` 和
`CCPANES_BROWSER_CHANNEL`。在 Windows 上可将 channel 设为 `msedge`。
测试入口只打包相关终端代码，通过独占临时端口服务合成数据，并模拟 checkpoint 上传。
它不连接实际 daemon，也不操作用户会话；结束后关闭浏览器和测试 HTTP 服务。

覆盖 DOM/WebGL × 历史阅读/底部跟随四种组合，每次回放约 810 万字符的重复刷新指令，
逐像素核对回放期间的终端内容（排除滚动条淡出动画），检查最终阅读位置及精简快照。
临时目录保留前、中、后三张截图和 results.json。

Windows Edge 验证不等同于 Windows WebView2 客户端的长时间后台验收。
