# 58. 功能提示（Feature Tips）：让积累的能力自己冒出来

> 2026-07-25 立项。起因：用户给出目标形态截图（双栏 TIP 弹窗：左 TIP 徽标+标题内联键位+说明+Got it，右侧功能演示），并提出「我们整理的很多东西，最后都要偶尔出现 tip 来试试」。
>
> 本质问题：CC-Panes 的能力增长速度远超用户发现速度——skill 体系、派工编排、右坞、布局密度、浏览器 tab、AI 面板、worktree 隔离……绝大多数用户永远不会知道它们存在。引导（docs/56）只覆盖头 5 分钟；**tips 覆盖之后的所有日子**。

## 1. 组件层：`FeatureTip`

基于 `GuidedDialog` 的一层薄封装，形态锁定截图：

- 左栏：`TIP` 徽标（小写字距徽章）→ 标题（可内联**键位 chip**）→ 正文 2 行内 → 重绑入口「随时重新绑定快捷方式 设置 → 快捷键」→ footer 按钮；
- 右栏：**纯 CSS/内联 SVG 演示**（禁止截图——截图会随 UI 改动腐烂，且暗色/亮色两套要各出一张）；演示应是该功能的 3-5 秒静态或极轻动画，遵守 `prefers-reduced-motion`；
- footer：主按钮「试试看」（直接执行该功能，把被动提示变成一次真实使用）+ 次按钮「知道了」。**截图里只有 Got it，我们加主行动**——tip 的价值在于用户真的用一次，而不是读一句话。

### 1.1 键位真值（硬约束）

键位 chip **必须**从 `settings.shortcuts.bindings[actionId]` 实时读取 + `formatKeyCombo()` 渲染，绝不硬编码：

- 用户改过绑定 → tip 显示改后的键；
- 该 action 未绑定 → **隐藏 chip**，文案降级为「去 设置 → 快捷键 绑定一个」，绝不教一个按下去没反应的键；
- 平台差异（Ctrl/Cmd）走既有格式化逻辑。

> 教错快捷键比不教更糟：用户按一次没反应就再也不信 tip 了。

## 2. 内容层：Tip 注册表

```
interface FeatureTip {
  id: string;                  // 稳定 id，seen 记录以此为键
  actionId?: string;           // 关联快捷键 action（决定 chip 与 try 行为）
  titleKey / bodyKey: string;  // i18n，中英双语
  visual: ComponentType;       // 右栏演示
  tryAction?: () => void;      // 「试试看」执行体
  eligible?: (ctx) => boolean; // 前置条件：功能可用才提（如无 worktree 就不提 worktree）
  weight?: number;             // 同批候选的相对权重
}
```

**流程规则（写进新功能 DoD）**：每个新功能落地时，同批提交它的 tip 条目——否则又是一个"做了但没人知道"的功能。这条比 tip 引擎本身更重要。

### 2.1 首批内容候选（均为**已存在**能力，逐条需核实后再写）

派工/编排线：worktree 隔离派工、leader/worker 自动反馈、skill 体系入口、AI 面板、fanout 对比。
日常线：布局两档密度、右坞（文件/Git）、浏览器 tab、命令面板、迷你模式、截图快捷键、Local History 版本回看、会话资源管理器。
高阶线：Provider 切换、目录扫描导入、工作空间迁移/同步、Git 时间线 Diff。

> 截图中的「Ctrl+Shift+J 跳转 worktree」**当前不存在**（命令面板无 worktree 条目，快捷键表无该绑定）——它是一个**候选新功能**（见 §5），不是首批 tip 内容。不要照抄截图内容做成 tip，否则教的是不存在的功能。

## 3. 时机引擎（决定成败的部分）

tip 系统失败只有一种方式：**烦人**。因此闸门优先于内容。

### 3.1 硬闸门（任一命中即不弹）

- 有 agent 正在 thinking / active / waitingInput（**绝不打断干活**）；
- 终端有焦点且用户 30s 内有输入；
- 已有 modal/dialog 打开；
- 应用启动后 < 5 分钟；
- 前 3 个会话（先让用户过完引导期）；
- 全屏/迷你模式/演示场景。

### 3.2 频率

- 每会话 ≤ 1 条；
- 两条之间 ≥ 3 天（可配置）；
- 用户连续 2 次点「知道了」而不点「试试看」→ 频率减半（它在告诉你它不感兴趣）；
- 设置项：功能提示 开/关（默认开）+「不再显示任何提示」。

### 3.3 出现时机（自然边界，不是随机时刻）

优先级从高到低：

1. **上下文触发（最有价值）**：观察到用户手动做了 N 次可被更快路径替代的操作（例：连续 3 次用鼠标菜单新建标签 → 提示 Ctrl+T；连续手动 cd 到 worktree → 提示 worktree 跳转）。需要一个**本地**动作计数器（不外传）；
2. **未用能力**：某功能可用但从未被使用过 X 个会话；
3. **随机兜底**：以上都没有时，在空闲边界（任务完成后用户静置 ≥ 20s、关闭某个面板后）低频抽一条。

MVP 可以只做 2+3，但 1 是这个系统真正的价值来源，不要长期缺席。

### 3.4 持久化

全局配置 `~/.cc-panes/config.toml`：

```toml
[tips]
enabled = true
lastShownAt = "2026-07-25T10:00:00Z"
seen = ["worktree-jump", "layout-density"]     # 展示过
tried = ["layout-density"]                     # 点过「试试看」
dismissRun = 0                                 # 连续「知道了」计数
```

跟随 dev/release 数据目录隔离（同 `APP_DIR_NAME`）。

## 4. 验收

1. 硬闸门逐条构造场景验证——尤其"agent 运行中绝不弹"；
2. 改键后 tip 显示新键；解绑后 chip 消失且文案降级；
3. 「试试看」真的执行功能（不是只关弹窗）；
4. 关闭开关后永不出现；`seen` 内的 tip 不重复；
5. reduced-motion 下右栏演示不动画；暗/亮色各看一遍；
6. i18n 中英双语齐全。

## 5. 衍生候选：worktree 快速跳转（截图内容的产品化）

截图里那条 tip 演示的功能本身值得做，且与我们重度使用 worktree 派工的工作流高度契合：

- 命令面板（Ctrl+K）内或独立快捷键，搜索 worktree/分支名 → 回车切换；
- 列表项显示分支名 + 状态点（有无未提交改动 / 是否 prunable）；
- 搜索无命中时提供「创建工作树"<输入>"」行动项（截图里正是这一条）；
- 与 `git worktree list` 实时对齐，prunable 的给清理入口。

做成之后，它自己就是首批 tip 里最好的一条——形态与截图完全一致。
