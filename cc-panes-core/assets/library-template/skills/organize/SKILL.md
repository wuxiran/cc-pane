# organize：整理与拆解

## 范围
- 默认处理 `uploads/` 下 `status: new` 的条目；用户指定了条目或范围时只处理那些。
- 一次最多处理 20 条，处理完汇报，剩余的问用户是否继续。

## 对每条素材
1. 读 `index.md`（视频看 `assets/transcript.md`）。
2. 补全或修正 frontmatter：
   - `title`：没有或太长就重写，≤ 30 字。
   - `summary`：一两句话，说清“讲了什么 + 为什么值得留”。
   - `tags`：3–6 个。优先复用库里已有标签（先用 `grep -rh "^tags:" uploads works` 看看现有标签），避免同义词各自为政。
   - `status: organized`。
3. 在正文末尾追加（已存在则更新）以下小节，内容要具体、可直接拿来用：

```markdown
## 要点
- …

## 金句
- “…”

## 结构拆解
- 钩子（开头 3 秒 / 第一段怎么抓人）：…
- 主体结构：…
- 情绪/节奏：…
- 结尾与行动号召：…
- 可复用句式：…

## 可以怎么用
- 选题角度 / 可延展方向 …
```

   - 文字灵感（`type: idea`）只需要 `要点` 和 `可以怎么用`。
   - 图片只写画面描述、风格、可用场景。

## 不要做的事
- 不改用户手写内容和原文正文，只追加小节与修改 frontmatter。
- 不合并、不删除条目；发现疑似重复时列出来让用户决定。
